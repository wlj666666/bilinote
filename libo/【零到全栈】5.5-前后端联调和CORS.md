## 6. CORS 原理与跨源定义 [原片 @ 15:30](https://www.bilibili.com/video/BV13M3U6HEnk?t=930)

- CORS（Cross-Origin Resource Sharing，跨源资源共享）是**浏览器强制执行的安全策略**，非 HTTP 协议限制。
- “源（Origin）”由三部分唯一确定：**协议（scheme） + 域名（host） + 端口（port）**。三者完全一致才视为同源。
- 本例中：前端 `http://localhost:3000` 与后端 `http://localhost:8000` 协议、域名相同，但端口不同 → 属于**跨源**（亦称“跨域”，但“跨源”更准确）。
- CORS 核心规则：浏览器允许跨源请求发出，但**禁止 JS 脚本读取未经授权的跨源响应**。
- 授权方式：后端响应中必须包含 `Access-Control-Allow-Origin` 响应头，且其值需匹配请求源（如 `http://localhost:3000`）或为通配符 `*`（不适用于带凭据请求）。

## 7. 使用 CORSMiddleware 解决简单请求（GET） [原片 @ 18:55](https://www.bilibili.com/video/BV13M3U6HEnk?t=1135)

- FastAPI 提供 `CORSMiddleware` 中间件，用于统一为所有响应添加 CORS 相关响应头，避免在每个路由中重复设置。
- 添加方式（在 `main.py` 中）：
  ```python
  from fastapi.middleware.cors import CORSMiddleware

  app = FastAPI()

  app.add_middleware(
      CORSMiddleware,
      allow_origins=["http://localhost:3000"],  # 允许的源列表
      allow_credentials=True,                    # 是否允许携带凭据（如 cookies）
      allow_methods=["*"],                       # 允许的 HTTP 方法（暂用通配符）
      allow_headers=["*"],                       # 允许的请求头（暂用通配符）
  )
  ```
- 修改后保存，FastAPI 热重载生效。
- 验证：Network 面板中 `GET /api/profile` 的 Response Headers 出现 `Access-Control-Allow-Origin: http://localhost:3000`；页面成功显示“来自后端”标识。

## 8. 预检（Preflight）机制与 OPTIONS 请求 [原片 @ 24:17](https://www.bilibili.com/video/BV13M3U6HEnk?t=1457)

- 当前端发起**非简单请求**（如 `POST` 且 `Content-Type: application/json`）时，浏览器会**自动前置发送一个 `OPTIONS` 请求**进行预检（preflight）。
- 简单请求判定（满足任一即为非简单）：
  - 请求方法非 `GET`、`HEAD`、`POST`；
  - 请求头包含非“安全头”（如 `Content-Type` 值非 `application/x-www-form-urlencoded`、`multipart/form-data`、`text/plain`）；
  - 使用了 `XMLHttpRequest` 的 `setRequestHeader()`。
- 本例中 `POST /api/analyze` 因 `Content-Type: application/json` 触发预检。
- 预检目的：防止有副作用的请求（如创建订单、发评论）在未获授权前就执行。浏览器先问后端：“我能否用 `POST` 方法向你发这个请求？”——若后端拒绝，真正的 `POST` 根本不会发出。
- 此时 `CORSMiddleware` 默认未配置 `allow_methods`，导致预检 `OPTIONS` 请求返回 405 或无许可头，进而阻断后续 `POST`。

## 9. 完善 CORSMiddleware：allow_methods 与 allow_headers [原片 @ 29:10](https://www.bilibili.com/video/BV13M3U6HEnk?t=1750)

- 为使预检通过，需在 `CORSMiddleware` 配置中明确声明允许的方法：
  ```python
  app.add_middleware(
      CORSMiddleware,
      allow_origins=["http://localhost:3000"],
      allow_credentials=True,
      allow_methods=["GET", "POST"],  # 显式添加 POST
      allow_headers=["*"],             # 允许所有请求头（可选，VS Code 自动提示）
  )
  ```
- `allow_headers=["*"]` 表示接受任意请求头（包括 `Content-Type: application/json`），避免因请求头不被允许而导致预检失败。
- 验证：Network 面板可见两个请求：
  - `OPTIONS /api/analyze`（Preflight），状态 `200`；
  - `POST /api/analyze`（主请求），状态 `200`，响应数据正确渲染。

## 10. 前端环境配置管理：.env.local [原片 @ 33:37](https://www.bilibili.com/video/BV13M3U6HEnk?t=2017)

- 问题：API 地址 `http://localhost:8000` 在前端代码中硬编码，不利于多环境（开发/测试/生产）部署。
- 解决方案：使用 Next.js 内置的环境变量机制。
- 步骤：
  1. 在前端项目根目录（与 `package.json` 同级）创建 `.env.local` 文件；
  2. 写入：`NEXT_PUBLIC_API_BASE_URL=http://localhost:8000`；
     - `NEXT_PUBLIC_` 前缀表示该变量可暴露给浏览器端代码（仅限公开配置，密钥等敏感信息不可用此前缀）；
  3. 在 `HomeView.tsx` 和 `InputCard.tsx` 中，将硬编码地址替换为 `process.env.NEXT_PUBLIC_API_BASE_URL`；
  4. **重启前端开发服务器**（`.env.local` 在启动时加载，保存后需重启才生效）。
- 验证：功能正常，Network 请求 URL 变为 `http://localhost:8000/api/...`。

## 11. 总结与后续模块预告 [原片 @ 38:22](https://www.bilibili.com/video/BV13M3U6HEnk?t=2302)

- 完整链路回顾：浏览器发起请求 → （复杂请求触发）预检 `OPTIONS` → 后端 `CORSMiddleware` 拦截并添加 CORS 响应头 → API 处理 → 中间件再次处理响应 → 浏览器校验 `Access-Control-Allow-Origin` → 允许 JS 读取响应。
- 实践要点强调：
  - CORS 是浏览器行为，`curl` 等工具不受限；
  - `GET` 等简单请求可绕过预检，但响应仍受 `Access-Control-Allow-Origin` 控制；
  - 配置应集中管理（如 `.env.local`），避免散落各处；
  - 后端代码中类似 `http://localhost:3000` 的前端地址也属环境配置，后续部署章节将统一处理。
- 当前遗留问题：
  - `/api/analyze` 返回的情感分析结果仍是占位符（拼音、固定分数），未真正计算；
  - 分析结果无历史记录，每次提交后即丢失。
- 下一模块（Module 6）目标：接入 Python 第三方库实现真实文本分析，并引入数据库保存用户查询历史。
