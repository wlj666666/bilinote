# OCR 路线验证记录

以下保留最初 CPU 实现的验证记录。后续 GPU 改造、最终修正后的全片验证及性能对照见 [OCR_GPU_VALIDATION.md](OCR_GPU_VALIDATION.md)。

验证环境：2026-09-14，当前 Linux 源码工作区，`bilinote` Python 环境；RapidOCR 3.9.2，CPU 单线程，默认 5 fps。

- 覆盖：平台字幕优先、OCR/ASR 分支隔离、失败禁止自动回退与总结、输入/路线缓存隔离、静态文字和弹幕排除、位置切换、尾段静态字幕延续、时间轴、数字/否定词/运算符保护、子进程停滞终止。
- 网页：`npm run build` 通过。
- 浏览器插件：生产构建和类型检查通过。
- 网页完整 TypeScript 检查仍有仓库既有错误（例如 Markdown 版本联合类型、部分组件属性和未使用变量）；生产构建通过不代表全仓类型检查通过。未进行浏览器交互自动化。

## 真实 B 站视频

样本：工作区已有 `BV1CuNd6GECx.mp4`，409.4 秒，1080×1920。画面同时包含讲话字幕、长篇静态提问正文和水印。

- 完整扫描成功，272 条片段；本机耗时 1393.7 秒（约 23 分 14 秒）。这是最后两处修正前的全片实测，不代表所有硬件的性能。
- 20 个定位成功的窗口均位于画面上方的讲话字幕区域，下边界小于画面高度的 40%，排除了下方长篇正文。能读到 `Python`、`LeetCode`、`Agent`、`C/C++` 等原文。
- 全片结果暴露了衣服图案被读为 `3`、`Y` 等单字符，以及末句截断的问题。随后增加了针对区域边缘单字符形状的过滤，以及片尾对已确认字幕区域的延续；实测误识别坐标、正常单字和英文长句均有回归测试。
- 对真实最后 49.4 秒重新提取，得到 31 条片段，最后两句为“能够找去一个知名企业实习”“就OK了好吧”，结束于原视频约 401.8 秒；没有把关注画面文字当作讲话字幕。区域缺失为 0 秒，低分比例为 0。
- 该尾段单独作为短片时返回 `uncertain`：最后 7.6 秒片尾空白超过短片 15% 的阈值。这是当前保守质量规则的明确限制，不应表述为该短片整条生成成功；实际测试没有将它交给总结模型。
- 最后两处修正后验证了自动化测试、四类合成视频以及真实尾段，没有再次重跑整条 409.4 秒视频，也没有人工逐字标注准确率。

## 验证边界

本次不调用付费总结模型、不重新联网下载视频、不验证桌面可执行文件打包。局部 OCR 错字、字幕区域误判和不足采样间隔的短字幕仍可能发生；质量检查用于阻止明显不可靠的结果，不是准确率保证。
