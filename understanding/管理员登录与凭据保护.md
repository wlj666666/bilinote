# 管理员登录与凭据保护

本阶段保留现有管理员设置页面、Cookie 回显及 API Key 编辑行为，通过服务端权限限制客户读取配置。

## 首次启用

使用后端运行时的 Python 环境，在 `backend/` 目录执行：

```bash
python scripts/manage_users.py init-admin yourname
```

命令交互读取两次密码，要求 12–128 个字符。没有默认账号或默认密码。命令使用当前 `DATABASE_URL`；默认是当前工作目录中的 `bili_note.db`，因此需在与后端启动相同的工作目录和环境执行。已有供应商、模型、Cookie 配置沿用。

重启后端和前端后，使用创建的账号登录。管理员在“设置 → 客户账号”中创建客户、停用账号和重置客户密码。停用或重置密码会立即撤销该账号的旧会话。

登录页也提供“立即注册”。用户只需设置账号和密码，确认密码后即可注册并自动登录；所有自注册账号固定为已启用的普通用户，不能通过注册接口获取管理员权限。账号统一转为小写，要求 3–64 位字母、数字、下划线、点或短横线，密码要求 12–128 个字符。暂不收集邮箱，也不提供用户自助找回密码流程；保留已有的管理员手动重置能力。

管理员的账号列表显示用户 ID、账号、角色、启用状态、注册时间、最近登录时间和当前未删除的笔记任务数（包括处理中及失败任务）。列表只统计任务数量，不读取笔记或聊天内容，不返回密码或令牌。旧账号没有记录的时间显示为未知；后端启动时自动添加时间字段，保留原账号、密码哈希及权限。

管理员忘记密码时，在服务器的相同环境执行：

```bash
python scripts/manage_users.py reset-password yourname
```

也可用 `create-user USERNAME` 从服务器命令创建普通用户。

## 权限与调用

| 接口 | 权限 |
| --- | --- |
| `GET /api/sys_check` | 公开，仅返回存活状态 |
| `POST /api/auth/login` | 公开；每个来源地址每分钟最多 10 次尝试 |
| `POST /api/auth/register` | 公开；每个来源地址每分钟最多 10 次尝试，与登录单独限流 |
| `/api/auth/me`、`/api/auth/logout` | 已登录 |
| `/api/auth/users`、`/api/auth/users/{id}` | 管理员 |
| 供应商、模型管理、Cookie、转写、代理、详细诊断接口 | 管理员 |
| `GET /api/available_models` | 已登录；只返回模型标识、供应商标识、名称、读图能力 |
| 上传、提交任务、查询结果、图片代理、AI 问答 | 已登录 |

管理接口沿用原 URL。普通用户调用返回 HTTP 403，未登录或会话过期返回 HTTP 401。客户端只使用已保存且供应商已启用、已配置凭据的模型；任务提交和问答都会重新检查。当前以保存模型及供应商启用开关控制开放范围。

登录和注册返回随机 Bearer 会话令牌，客户端请求使用 `Authorization: Bearer <token>`。默认在浏览器 `sessionStorage` 中保存，刷新页面保留，关闭标签页后需要重新登录；有效期为 12 小时。勾选“记住我”后，令牌保存在同一浏览器的 `localStorage` 中，有效期为登录或注册后的 30 天，重新打开网页会校验会话并恢复登录。退出或登录失效时清除两种存储；记住登录的标签页之间同步账号切换与退出，清空前一个用户的前端状态。网页不保存明文密码，账号密码自动填充由浏览器密码管理器控制。数据库只保存令牌摘要和带独立盐的密码哈希。模型 API Key、下载 Cookie 不作为登录令牌，也不发送给普通用户。

API 响应禁止缓存；退出、登录过期时清空前端供应商／模型状态。旧登录状态下发出的请求即使稍后返回，也不会写入当前用户状态。封面通过带认证的请求获取 Blob，令牌不出现在图片 URL 中。

任务结果会过滤下载元数据中的 Cookie、请求头和凭据字段，失败任务对客户返回简洁错误。日志格式化时对已配置凭据脱敏，SQL 错误隐藏参数。管理员的现有配置接口保留原回显行为。

客户提交的链接需与所选平台域名匹配，并统一使用 HTTPS。上传只接受媒体文件，以随机前缀保存；本地处理仅接受上传目录中的媒体文件，任务标识不能包含路径。快手分享链接解析请求不携带平台 Cookie。

旧扩展或其他 API 客户端也需要登录并携带 Bearer 令牌；React 网页／桌面界面已接入登录。对外部署使用 HTTPS，并保证平台凭据所在的后端部署在运营方服务器上。

## 本阶段边界

管理员／客户权限及平台凭据保护已完成。后续已加入笔记、文件、聊天、向量索引和浏览器状态隔离，见[用户数据隔离与旧历史迁移](用户数据隔离与旧历史迁移.md)。

本阶段沿用服务器现有凭据存储格式；没有对现有供应商、Cookie 文件做加密迁移，也没有更换数据库或引入任务队列。

## 验证

```bash
cd backend
python -m pytest tests/test_auth_access.py tests/test_registration.py tests/test_user_isolation.py -q
cd ../BillNote_frontend
npm run test:auth
npm run build
```

权限测试使用临时数据库、配置与文件，并模拟任务执行，不调用付费模型。覆盖所有管理接口拒绝访问、管理员回显和编辑、客户模型白名单、会话撤销、路径限制、错误脱敏及结果中的下载凭据过滤。
