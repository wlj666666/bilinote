## 问题与修复

原 Agent 在 `resume-08` 工具轮数耗尽后继续返回工具调用，最终答案为空；
`resume-02` 则将“继续获取第三点的完整内容”作为结果返回。其最终供应商响应仍然是
`finish_reason=tool_calls`。仅省略 `tools` 并不能确保兼容网关停止调用工具。

问答代码现在在最后一次请求显式设置 `tool_choice="none"`，要求基于现有证据直接回答，
并拒绝最终仍请求工具、没有文本或只有空白的结果。4 项针对性回归覆盖正常直接回答、
工具轮数上限、空回答、供应商忽略关闭指令。修复后上述两题均给出完整有效文本。
没有更改生产的 3 轮工具调用上限或默认温度。

修复后仍有三个失败：

- `fastapi-04`：回答了 422，但未找到原文把 text 写成 txt 的细节；宽时间窗口查询被
  50 条返回上限截断，预算内未进一步缩小到正确片段。没有将这个部分正确结果计为通过。
- `fastapi-02`：首个模型请求返回供应商 HTTP 403。
- `resume-07`：已取得标注证据，但第二个模型请求返回供应商 HTTP 403。

没有补跑这三题来抬高最终指标。修复后的总通过率低于原 Agent 的 95.0%，本次不声称
关闭工具的修复提升了总体通过率；修复解决的是工具预算耗尽后的无效最终结果。

## 评分器纠错

初次 v1.0 规则得分是 RAG 25/40、原 Agent 37/40、修复后 Agent 37/40。
复核发现时间题不应要求重复目标句数字，以及 ASGI 服务、接口约定不变、证书名称、
“没有实测数据”等合理同义表述被误扣。保留 v1.0 原始分数，同时以 v1.1 同一规则
重评全部 120 条答案，得到本报告的 29/40、38/40、37/40。没有修改问题、删除题目、
改变原始模型回答或放宽 ±2 秒的时间容差。评分规则的变化没有被算作模型提升。

规则评分仍有局限：关键词命中不能发现所有否定、逻辑关系与附加事实问题。例如原 Agent
`session-08` 的主结论正确，但附带原文时间写成 26:38，实际对应约 43:58；该题并非时间题，
规则没有检查这个附带时间。因此本报告不能用来宣称“全部引用正确”或“没有幻觉”。
证据覆盖率检查的是指定证据片段是否进入模型上下文；其他同义证据也可能足以支持回答。

## 性能与成本取舍

Agent 补查提高材料覆盖，但增加模型往返、上下文与耗时。本次修复后已返回的 token 总量
约为 RAG 的 4.59 倍，平均耗时约 1.67 倍。403 请求未返回 usage，因此 token 数只是已知用量，
不是含失败请求的精确账单。没有核验该网关当前价格，故不填写人民币成本或“成本降低”。
P95 来自每配置 40 个样本，包含客户端侧请求耗时，不能当作线上服务 SLA。
