## 1. 核心概念：数据驱动界面 [原片 @ 00:00](https://www.bilibili.com/video/BV1Dg7H6oEHQ?t=0)

*   **背景**：上一节将项目从 vanilla 改造为 React 项目，网站由组件搭建而成。本节核心是将网站的内容和结构分开。
*   **核心思想**：React 除了组件化，另一个重要概念是**把操作页面变成改变数据**。
    *   不再一行行命令页面显示什么。
    *   只管修改背后的数据，页面会根据数据自动长成该有的样子。
*   **案例回顾**：
    *   `PageHeading` 组件：标题位置留空，喂给它什么字（如“关于我”或“文字实验室”），它就显示什么。
    *   `App` 组件：手里揣着一个值（如 `page="home"` 或 `page="text-lab"`），决定当下显示哪个 Page。
    *   **结论**：页面说到底就是照着一些值在显示，值是什么页面就长什么样。

## 2. 玩法一：数据与界面分离 [原片 @ 03:34](https://www.bilibili.com/video/BV1Dg7H6oEHQ?t=214)

*   **场景**：项目完成后，数据（如标题、作品卡片）变动频繁，而页面结构变动较少。
*   **做法**：
    *   创建专门的数据文件（如 `src/data/site.js`），集中存储内容（title, subtitle, works 等）。
    *   组件（如 `HomePage`）不再写死文案，只负责从数据表中取出对应字段的值进行显示。
*   **细节**：这种数据文件格式像 JSON，但 JS 对象大括号内最后一项可以带逗号，JSON 不行。
*   **优势**：
    *   **分工明确**：组件管“怎么显示”（排版、样式、结构），`site.js` 管“显示什么”（文字内容）。
    *   **便于管理**：改文案、加作品只需改动 `site.js`，组件代码无需触碰。
    *   **便于国际化**：若做英文版，只需准备一份英文内容表，组件根据用户选择读取对应表，无需在组件内写大量判断逻辑。
    *   **为后端对接做准备**：未来数据可从网络 API 实时获取，架构无需大改。

## 3. 玩法二：组件状态（State） [原片 @ 12:26](https://www.bilibili.com/video/BV1Dg7H6oEHQ?t=746)

*   **场景**：有些数据需要在用户操作（如打字、点击）时实时变化，并驱动界面更新。
*   **概念**：在 React 中，这种会变且一变界面就跟着变的数据叫做**组件的状态（state）**。
*   **案例**：文字实验室的“已输入多少字”。
    *   输入框内的文字是 state。
    *   打字动作改变 state，下方的字数统计照着 state 自动计算并刷新。
*   **特点**：State 只生存在当前页面。刷新页面后，state 丢失，界面回到初始化状态（如字数归零）。
*   **应用**：`App` 组件切换页面也是靠 state（记录当前在哪一页），点击导航栏即改变该 state。

## 4. 玩法三：URL 驱动（路由） [原片 @ 15:58](https://www.bilibili.com/video/BV1Dg7H6oEHQ?t=958)

*   **问题**：仅用 state 管理路由（页面切换）存在缺陷。
    *   **刷新丢失**：在“文字实验室”页面刷新，state 丢失，`App` 无法管理路由，页面跳回默认的“关于我”。
    *   **分享失效**：复制当前 URL 发给朋友，朋友打开看到的也是默认页，而非分享时的页面。
*   **解决**：将“现在在哪一页”这个值记在 **URL** 里。
    *   URL 刷新不消失，可整条复制，天然适合做路由管理。
*   **实现**：Demo 中通过一个 `router` 文件（手搓的小路由），在点击导航时修改 URL。
    *   效果：刷新页面保持当前页，支持浏览器前进/后退，链接分享有效。
*   **补充**：
    *   成熟项目通常使用 `react-router` 库，但本课下一节将引入 `Next.js`，它天然提供成熟的路由方案，故此处仅需理解概念。
    *   后端数据驱动（如文本情感分析结果）也是数据驱动界面的一种，本课暂不演示。

## 6. 工程化项目部署上线 [原片 @ 29:18](https://www.bilibili.com/video/BV1Dg7H6oEHQ?t=1758)

*   **背景变化**：
    *   之前（Vanilla 项目）：Nginx 直接指向源码目录，浏览器直接读取 HTML/CSS/JS。
    *   现在（Vite + React 项目）：浏览器不认识框架写法，必须先构建（`npm run build`）生成普通的 HTML/CSS/JS（即 `dist` 目录）。且 `dist` 通常在 `.gitignore` 中，不提交到仓库。
*   **部署流程**：
    1.  **服务器环境准备**：安装 Node.js（推荐用 nvm 或官网命令，版本较新）。验证 `node -v` 和 `npm -v`。
    2.  **代码同步**：本地 `git push`，服务器 `git pull`。
    3.  **安装依赖**：服务器执行 `npm install`（根据 `package.json` 安装）。
    4.  **构建产物**：服务器执行 `npm run build`，生成 `dist` 目录。
    5.  **配置 Nginx**：修改配置，将 `root` 指向 `.../zero-to-tech/dist`（而非源码目录）。
    6.  **重载服务**：`sudo nginx -t` 测试配置，`sudo systemctl reload nginx` 生效。
*   **后续维护**：每次改代码发布，需在服务器 pull 代码后重新 build。若 `package.json` 变动，需重新 install。

## 7. 遗留问题与下节预告 [原片 @ 38:10](https://www.bilibili.com/video/BV1Dg7H6oEHQ?t=2290)

*   **现象**：部署后，访问首页正常，但直接访问或刷新 `/text-lab` 页面会出现 **404 Not Found**。
*   **原因**：服务器（Nginx）在 `dist` 目录下找不到名为 `text-lab` 的文件（因为这是前端路由模拟的路径，并非真实文件）。
*   **预告**：这是现代前端项目上线的典型问题。下一节将从这个 404 讲起，引出 **Next.js** 框架来解决此问题。

## 8. AI 总结

本节课深入讲解了 React 中“数据驱动界面”的核心理念，即通过改变数据而非直接操作 DOM 来更新视图。视频详细演示了三种数据管理方式：
1.  **静态数据分离**：将文案等内容抽离至 `site.js`，实现内容与结构解耦，便于维护和国际化。
2.  **组件状态（State）**：处理用户交互产生的动态数据（如输入字数），实现局部实时刷新。
3.  **URL 路由**：将页面状态存入 URL，解决刷新丢失和分享失效问题。

最后，课程完成了从本地开发到服务器部署的完整流程升级，强调了现代前端工程化项目中“先构建后部署”的关键步骤，并留下了 SPA 路由刷新 404 的悬念，为引入 Next.js 做铺垫。
