## 1. 为什么需要 FastAPI：从手搓 API 到框架的价值 [原片 @ 00:00](https://www.bilibili.com/video/BV1LW3K63ExS?t=0)

- 上一节通过 Python 内置 `http.server` 手搓了一个仅支持 GET 的 `/api/profile` 接口，过程繁琐：
  - 需手动判断 HTTP 方法（如 `do_GET`）、路径（如 `if self.path == "/api/profile"`）；
  - 需手动设置响应状态码（`200`）、`Content-Type: application/json`；
  - 需手动调用 `json.dumps()` 转换字典、`encode()` 编码为 bytes；
  - 需手动处理 404 路径未匹配逻辑；
  - 若扩展 POST 接口，还需额外解析请求体、校验字段格式。
- 实际业务需求极简：**当访问 `/api/profile` 时，返回 profile 数据**；其余均为 HTTP 协议层面的“杂活”。
- 后端框架的核心价值：**封装 HTTP 底层细节，让开发者专注业务逻辑**。
- 框架定义：一套“管某一摊事”的规则——React 管 UI 组件，后端框架管“接收请求 → 解析内容 → 匹配路由 → 执行逻辑 → 发送响应”。

## 2. Python 主流后端框架对比：Flask、Django、FastAPI [原片 @ 02:29](https://www.bilibili.com/video/BV1LW3K63ExS?t=149)

- **Flask**：老牌轻量级框架，生态成熟，长期作为 Python 后端入门经典。
- **Django**：大而全的“全栈式”框架，自带后台管理界面、用户系统、ORM（数据库操作工具）等开箱即用功能。
- **FastAPI**（本节选用）：
  - 更年轻、更智能，**专为 API 开发设计**；
  - 支持基于类型提示（type hints）的**自动请求解析与数据校验**；
  - **自动生成交互式 API 文档**（基于 OpenAPI + Swagger UI）；
  - 性能优秀；
  - 官方文档质量极高（含中文版），兼具“用户手册”与“手把手教程”属性。

## 4. FastAPI 与 uvicorn 的职责分工 [原片 @ 05:27](https://www.bilibili.com/video/BV1LW3K63ExS?t=327)

- 手搓代码中同时承担两类工作：
  - **定义接口逻辑**（判断路径、组织响应）；
  - **运行服务**（监听端口、`serve_forever` 等待请求）。
- 使用框架后职责分离：
  - **FastAPI**：仅负责**定义接口**（路由、请求处理、响应生成）；
  - **uvicorn**：作为 ASGI 服务器，负责**运行服务**（监听端口、接收请求、转发给 FastAPI 处理）。
- 关系总结：FastAPI 决定“接口做什么”，uvicorn 负责“让接口跑起来”。

## 5. 安装 FastAPI 及其标准依赖 [原片 @ 06:26](https://www.bilibili.com/video/BV1LW3K63ExS?t=386)

- 安装命令（来自官网简体中文文档）：
  ```bash
  pip install "fastapi[standard]"
  ```
- `[standard]` 是 pip 的“套餐”语法，表示安装 FastAPI 本体 + **官方推荐的标准依赖包**，其中包含：
  - `uvicorn`（ASGI 服务器）；
  - `pydantic`（数据解析与校验核心库）；
  - 其他间接依赖（如 `starlette`, `jinja2` 等）。
- 安装后终端会显示大量已安装包列表，验证 `uvicorn` 和 `pydantic` 已随套餐一同安装。

## 6. 用 FastAPI 重写 GET 接口：代码对比与优势 [原片 @ 09:18](https://www.bilibili.com/video/BV1LW3K63ExS?t=558)

- 新文件 `main.py`（原手搓代码重命名为 `handmade.py`）：
  ```python
  from fastapi import FastAPI
  app = FastAPI()
  profile = {"name": "张三", "age": 25, "city": "北京"}
  @app.get("/api/profile")
  def get_profile():
      return profile
  ```
- 与手搓版对比优势：
  - **路由声明**：`@app.get("/api/profile")` 替代 `if self.path == ...`；
  - **状态码**：无需手动写 `200`，FastAPI 默认返回；
  - **Content-Type**：无需手动设置，自动识别 JSON 并设置头；
  - **JSON 序列化**：`return profile` 自动 `json.dumps()` + `encode()`；
  - **404 处理**：未定义路径自动返回 `404 Not Found`（JSON 格式响应）；
- 结论：代码极度简洁，HTTP 细节被完全封装。

## 7. 启动服务：uvicorn 与 fastapi dev 命令 [原片 @ 13:01](https://www.bilibili.com/video/BV1LW3K63ExS?t=781)

- 启动命令（两种等效方式）：
  - `uvicorn main:app --reload`  
    （`main` 指 `main.py` 文件，`app` 指文件内 `app = FastAPI()` 实例；`--reload` 启用热更新）
  - `fastapi dev`  
    （FastAPI 官方 CLI，内部调用 uvicorn，默认查找 `main.py:app`，更简洁）
- 启动后终端输出关键信息：
  - `Uvicorn running on http://127.0.0.1:8000`（服务地址）；
  - `Documentation at http://127.0.0.1:8000/docs`（交互式文档地址）；
- 热更新效果：修改 `main.py` 保存后，服务自动重启，无需手动退出再启动。

## 9. 添加 POST 接口：请求体定义与自动校验 [原片 @ 20:55](https://www.bilibili.com/video/BV1LW3K63ExS?t=1255)

- 新增接口目标：`POST /api/analyze`，接收文本并返回分析结果（本节先返回模拟数据）；
- 三处代码修改：
  1. **顶部导入**：`from pydantic import BaseModel`
  2. **定义请求体模型**：
     ```python
     class AnalyzeRequest(BaseModel):
         text: str
     ```
  3. **定义 POST 路由**：
     ```python
     @app.post("/api/analyze")
     def analyze(req: AnalyzeRequest):
         return {
             "original": req.text,
             "pinyin": "xxx",
             "score": 85,
             "sentiment": "positive"
         }
     ```
- `AnalyzeRequest` 的作用：
  - 声明请求体必须包含 `text` 字段且为 `str` 类型；
  - FastAPI 自动完成：**解析 JSON 请求体 → 校验字段存在性与类型 → 绑定为 `req` 对象**；
  - 若请求缺失 `text` 或类型错误，自动返回 `422 Unprocessable Entity` 及详细错误信息（如 `"missing"`）；
- 文档同步更新：`/docs` 中新增 `/api/analyze` 接口，明确列出 `requestBody` 要求。

## 10. 错误处理与调试：422 与 500 状态码分析 [原片 @ 27:19](https://www.bilibili.com/video/BV1LW3K63ExS?t=1639)

- **客户端错误（4xx）示例：422**
  - 场景：发送 POST 请求但 body 中字段名写错（如 `"txt": "hello"`）；
  - 响应：`HTTP/1.1 422 Unprocessable Entity` + JSON 错误详情（明确指出 `missing` 字段 `text`）；
  - 原因：FastAPI 基于 `BaseModel` 的**自动校验机制**拦截。
- **服务端错误（5xx）示例：500**
  - 场景：代码逻辑错误（如 `req.txt` 误写为不存在的属性）；
  - 响应：`HTTP/1.1 500 Internal Server Error`；
  - 调试关键：查看运行服务的终端输出的 **traceback（错误回溯）**：
    - 最后一行：`AttributeError: 'AnalyzeRequest' object has no attribute 'txt'`（错误原因）；
    - 往上找：定位到 `main.py`, `line 21`（错误位置）；
  - 注意：单次请求失败不影响服务进程，修复代码后热更新即可继续使用。
