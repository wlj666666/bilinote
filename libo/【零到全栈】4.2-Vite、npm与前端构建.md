## 前端模块化带来的三大痛点 [原片 @ 02:45](https://www.bilibili.com/video/BV1k3JA6cEAt?t=165)

- **痛点一：开发体验严重下降**  
  模块化后无法再双击 HTML 文件直接打开页面，必须依赖服务器；每次修改代码后，需走完整发布流程（提交 → push → 服务器 pull → 刷新），开发效率极低。

- **痛点二：浏览器请求爆炸，页面加载变慢**  
  模块化鼓励拆分文件（如 CSS 被拆成 8 个独立文件），导致浏览器需发起大量并行网络请求；视频演示 Network 面板中出现十几个请求长队，部分响应被拖至 800ms 甚至超 2s，显著拖慢首屏渲染。

- **痛点三：缓存失效导致更新不可见**  
  浏览器依据文件名匹配缓存；若仅修改 CSS 中一行代码但文件名未变，用户刷新后仍加载旧缓存，导致新功能/修复不可见。早年开发者曾手动在文件名后添加时间戳（如 `layout-20240101.css`）规避此问题。

> 注：主讲人明确指出，仅“痛点一”是模块化直接引入的新问题；“痛点二”与模块化倡导解耦有关；“痛点三”基础前端阶段即存在，并非模块化独有。

## 构建工具的核心价值：调和三方矛盾 [原片 @ 08:58](https://www.bilibili.com/video/BV1k3JA6cEAt?t=538)

- 三大目标存在内在张力：
  - **工程治理**：追求项目规范、安全、易维护、可扩展；
  - **开发者体验**：追求开发过程简单、顺手、高效；
  - **用户体验（浏览器/用户）**：追求页面加载快、资源少、性能高。
- 构建工具（Build tool）正是为调和这组矛盾而生：
  - 尊重工程规则（如模块化）；
  - 满足开发者便利性（如热更新、本地服务）；
  - 输出浏览器友好格式（如合并文件、添加哈希）。

## Vite 的定位与优势 [原片 @ 11:55](https://www.bilibili.com/video/BV1k3JA6cEAt?t=715)

- 当前前端构建工具首选，取代早期主流工具 Webpack。
- 名称源自法语 “vite”，意为“快”，读音为 `/vi:t/`，非英语 “vet”；作者为尤雨溪（Evan You），中国人。
- 三大能力精准解决前述三大痛点：
  1. **本地开发服务 + 热更新（HMR）**：执行 `vite` 命令启动本地 HTTP 服务（默认 `http://localhost:5173`），保存即自动刷新，无需手动点浏览器刷新按钮；
  2. **文件合并（Bundling）**：将开发时拆分的多个 CSS/JS 文件，在构建时合并为极少数文件（如 8 个 CSS → 1 个），大幅减少请求数；
  3. **文件哈希（Hashing）**：为输出文件名自动添加基于内容的哈希指纹（如 `index-CuLwmTeq.css`），内容变更则哈希变更，强制浏览器弃用缓存。

## Node.js 与 npm 的作用关系 [原片 @ 13:17](https://www.bilibili.com/video/BV1k3JA6cEAt?t=797)

- **Node.js**：JavaScript 的运行时环境，使 JS 脚本能脱离浏览器，在本地电脑（命令行）中执行；Vite 是用 JS 编写的命令行工具，必须依赖 Node.js 才能运行。
- **npm**：随 Node.js 自动安装的包管理器，本质是 JavaScript 生态的“应用商店”：
  - 与系统级包管理器（如 Ubuntu 的 `apt`）类比，但关键区别在于：`apt` 全局安装（整台机器一份），而 `npm` 默认按**项目**安装（各项目隔离，互不干扰）；
  - 不仅用于安装（如 `npm install vite`），还通过 `package.json` 的 `scripts` 字段管理项目脚本命令。

## npm 初始化与 package.json 解析 [原片 @ 17:50](https://www.bilibili.com/video/BV1k3JA6cEAt?t=1070)

- 在项目根目录执行 `npm init -y` 进行初始化，生成 `package.json` 文件，作为项目的“npm 账本”。
- `package.json` 是 JSON 格式文件（键值对结构，外层大括号 `{}`），用于记录：
  - 项目元信息（如 `name`、`version`）；
  - 依赖声明（后续填充）；
  - 可执行脚本（`scripts`）。
- 主讲人建议初学者掌握 JSON 基础语法，特别注意逗号规则：每项末尾需逗号，但**最后一项后不可加逗号**（否则语法错误）。
- 初始化后可精简 `package.json`，仅保留 `name`、`version` 及后续将使用的 `scripts`，删除无用字段（如 `description`、`main`）。

## 安装 Vite（开发依赖）与 node_modules 结构 [原片 @ 24:21](https://www.bilibili.com/video/BV1k3JA6cEAt?t=1461)

- 执行 `npm install -D vite` 安装 Vite：
  - `-D`（或 `--save-dev`）表示安装为**开发依赖（devDependencies）**，即仅用于开发构建阶段的工具（如脚手架），不参与最终上线产物；
  - 区别于**生产依赖（dependencies）**（如动画库），后者会打包进最终网站。
- 安装后生成两个关键文件：
  - `package.json` 新增 `devDependencies` 字段，记录 `"vite": "^8.0.16"`；
  - `package-lock.json` 锁定所有依赖的精确版本，确保不同环境安装结果一致。
- Vite 实际安装至 `node_modules/vite/`（代码主体）及 `node_modules/.bin/vite`（可执行命令入口）；`node_modules` 目录庞大，因 Vite 本身依赖大量其他包，形成依赖树。

## Vite 的三大核心命令：dev / build / preview [原片 @ 30:16](https://www.bilibili.com/video/BV1k3JA6cEAt?t=1816)

- `vite`（或 `npm run dev`）：**开发预览**。启动本地开发服务器，提供热更新，实时反映代码修改。
- `vite build`（或 `npm run build`）：**构建（打包）**。将源代码转换为生产就绪的静态资源，输出至 `dist/` 目录；该过程完成文件合并与哈希添加。
- `vite preview`（或 `npm run preview`）：**预览构建产物**。启动一个轻量 HTTP 服务器，专门服务于 `dist/` 目录，用于本地验证构建结果是否正确。

## 源代码 vs 构建产物（dist）的严格区分 [原片 @ 39:05](https://www.bilibili.com/video/BV1k3JA6cEAt?t=2345)

- **源代码（Source Code）**：
  - 位于项目根目录及子目录（`js/`, `css/`, `index.html`, `README.md` 等）；
  - 特点：多文件、结构清晰、可读性强、便于人类编写与维护；
  - 所有开发工作均在此进行。
- **构建产物（Built Output）**：
  - 位于 `dist/` 目录下；
  - 特点：文件极少、高度压缩、文件名含哈希、专为浏览器优化；
  - **严禁手动修改 `dist/` 内容**，因其在下次 `vite build` 时会被完全覆盖。

## 通过 scripts 配置短命令提升效率 [原片 @ 42:14](https://www.bilibili.com/video/BV1k3JA6cEAt?t=2534)

- `package.json` 的 `scripts` 字段可定义自定义命令别名，简化长命令输入。
- 推荐配置（符合行业约定）：
  ```json
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
  ```
- 执行方式：`npm run <script-name>`（如 `npm run dev`）。
- 此机制本质是 shell 命令代理：`npm run` 会优先在 `node_modules/.bin/` 查找命令，未找到则 fallback 至系统 PATH（如 `git --version`）。
- 命令名（`dev`/`build`/`preview`）为社区约定，非强制；但强烈建议遵守，以利协作、资料检索及 AI 辅助。

## gitignore 排除 node_modules 和 dist [原片 @ 48:40](https://www.bilibili.com/video/BV1k3JA6cEAt?t=2920)

- `node_modules/` 和 `dist/` 是由命令（`npm install`, `vite build`）**自动生成的产物**，非源代码，不应提交至 Git 仓库。
- 原因：
  - 体积巨大，拖慢远程同步速度；
  - 可随时通过 `package.json` + `package-lock.json` 重新生成（`npm install` 即可复原全部依赖）。
- 应在 `.gitignore` 文件中添加两行：
  ```
  node_modules/
  dist/
  ```
- 添加后，Git 将忽略这些目录的变更（文件状态变为灰色），仅跟踪真正需要协作的源代码。

## 将第三方库 anime.js 从 CDN 迁移至本地依赖 [原片 @ 50:20](https://www.bilibili.com/video/BV1k3JA6cEAt?t=3020)

- 当前 `anime.js` 通过 CDN URL（`https://cdn.jsdelivr.net/npm/animejs@...`）导入，存在风险：
  - 每次页面加载需额外网络请求（增加延迟，视频中达 600+ ms）；
  - 依赖外部服务稳定性，CDN 不可用则功能失效；
  - 无法锁定精确版本，更新可能引入不兼容变更。
- 迁移步骤：
  1. 执行 `npm install anime.js`（无 `-D`，即安装为**生产依赖** `dependencies`）；
  2. 修改源代码中 `import` 语句：将冗长 CDN URL 替换为简洁包名 `"animejs"`；
  3. 执行 `npm run build`：Vite 会自动解析 `"animejs"`，将其代码打包进 `dist/` 的 JS 文件中，彻底消除外部请求。
- 验证：`npm run preview` 后检查 Network 面板，确认请求仅剩 `index.html`、`index-xxx.css`、`index-xxx.js` 三个文件。
