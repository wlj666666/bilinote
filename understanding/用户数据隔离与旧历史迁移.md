# 用户数据隔离与旧历史迁移

管理员管理全局模型、Cookie、转写和客户账号；业务内容按用户隔离。管理员也默认只能查看自己的笔记、文件和聊天。登录身份由服务器验证，客户端提交的 `user_id` 不参与归属决定。

## 已有数据

当前工作区的迁移已将 62 条历史任务、95 个静态文件、3 个上传文件归到 `admin`（用户 ID 1）。43 条任务原本在数据库中，其余历史从磁盘结果／状态文件中补录。生成检查点产生的 `_markdown.status.json` 不作为独立任务显示。

迁移前的 SQLite 数据库备份位于 `backend/backups/user-isolation/`，包括加归属字段前及分配归属前的快照，文件权限为仅当前系统用户可读写。旧笔记、字幕缓存、截图、封面、上传和向量文件保留原位置，避免破坏现有引用。备份目录不会被文件接口公开。

管理员第一次在原浏览器登录时，会自动把旧 IndexedDB `task-storage` 中的笔记版本与表单选项，以及旧 `bilinote-chat-storage` 聊天记录导入服务器。所有导入请求成功后才清除旧浏览器副本。客户不会加载这些旧缓存。仅服务器能看到的文件无法包含浏览器独有的旧版本，因此需在原浏览器完成这一步。

服务器启动时会自动运行幂等迁移。重复运行仅登记未归属的旧数据，不覆盖已经属于其他用户的数据，也不会恢复已删除的任务。也可在后端运行环境、与后端相同的工作目录执行：

```bash
python scripts/migrate_user_data.py --admin admin
```

首次迁移可指定原管理员；完成后固定使用迁移记录中的管理员。缺少管理员时迁移等待初始化账号。

## 新数据的存储

| 内容 | 保存方式 |
| --- | --- |
| 任务归属、提交选项、笔记版本 | 数据库 `video_tasks`，按 `user_id` 过滤 |
| 结果、字幕、状态、模型检查点 | `note_results/users/<user_id>/`，任务 ID 区分文件 |
| 下载、视频帧、中间缓存 | 按用户及任务隔离的处理目录 |
| 截图、本地封面 | `static/users/<user_id>/<task_id>/`，数据库登记归属 |
| 上传 | `uploads/users/<user_id>/`，随机前缀防覆盖 |
| 向量索引 | `vector_db/users/<user_id>/`；管理员旧任务沿用旧索引并校验归属 |
| 聊天 | 数据库 `chat_entries`，同时绑定用户和任务 |

后台任务通过线程上下文传递固定身份与目录，不修改进程级环境变量。下载器按任务实例化，避免共享下载状态。模型权重和平台配置仍是运营方的全局资源。

## 页面与接口

网页／桌面界面登录后从服务器获取自己的任务历史。私有笔记与聊天不再持久化到共用浏览器缓存；当前选中任务和提取偏好按账号保存。退出、过期或切换账号时清空内存，旧会话的响应不能写入新账号状态。换浏览器或设备登录后仍可查看自己的历史和聊天。

- `GET /api/tasks`：当前用户任务，支持分页。
- `GET /api/task_status/{id}`：只能查询自己的任务。
- `POST /api/generate_note`：新任务归当前身份；重试必须拥有原任务。
- `POST /api/delete_task`：按任务 ID 删除；旧按视频 ID 的调用也只处理当前用户数据。
- `PATCH /api/tasks/{id}/display`：保存自己的笔记版本。
- `GET /api/tasks/{id}/export`：下载自己的 Markdown。
- `/api/chat/index`、`status`、`ask`、`history`：全部检查任务归属，问答使用服务器保存的历史。
- `GET /api/files/{kind}/{path}`：经过登录及文件归属检查才返回文件。

旧 `/static/`、`/uploads/` 路径也需要认证，已移除无权限的静态目录挂载。封面、历史缩略图和 Markdown 图片通过带认证的请求获取 Blob；私有上传链接以认证下载处理。URL 不包含账号会话令牌，文件响应禁止缓存，Nginx 不添加公开缓存头。

越权或不存在的资源统一返回 HTTP 404，未登录返回 401。任务处理中拒绝删除。删除成功后，`video_tasks` 中的任务整行、聊天及关联文件登记记录会实际删除；结果、字幕、OCR 诊断、GPT 检查点、任务独占图片及处理目录也会清理，向量索引同步删除。`deleted_tasks` 只保留用户 ID 和任务 ID，不保留笔记、字幕或生成参数，用于阻止旧浏览器历史、旧文件迁移和后台写入恢复已删任务。

旧的共用图片、共用音视频、用户原始上传及已有备份继续保留，避免影响其他笔记。新任务按用户和任务划分的处理目录可直接清理；旧 `data/media/<输入哈希>/<任务 ID>/` 目录只清理该任务的抽帧／拼图，不删除父目录中的共用媒体。无法确定归属的旧文件保留。清理失败会返回错误，保留删除标记及待清理任务／文件路径，可以重试；不会返回“删除成功”。删除与索引及聊天落库使用同一任务锁，避免并发写入重建已删除内容。

历史软删除任务可在停止后端后执行 `python scripts/purge_deleted_tasks.py --user admin --apply --compact`；省略 `--apply` 只查看数量。脚本只处理指定账号已标记删除的任务，不清理仍保留的任务。

2026-10-13 已按管理员授权清理 24 条历史软删除任务，删除 2,311 个独占文件，释放 540,340,672 字节（约 515 MiB）。保留 38 条任务，逐行核对其内容及账号、模型配置、会话未变，并校验 2,128 个保留文件的内容。重启后确认未恢复已删任务，相关笔记文件、独占处理目录及向量集合均已清除。已有备份及无法确定归属的共用文件保留。

缺少原始生成选项的旧任务会补充当前可用模型作为重试／问答默认选项，不据此认定它就是历史生成时使用的模型。

## 验证与后续

隔离测试使用临时数据库和模拟模型，覆盖两个客户与管理员的交叉读取、重试、编辑、下载、删除、问答、文件路径、向量检索、并发目录、旧结构备份与幂等迁移。浏览器验证覆盖原历史导入、私有图片、同浏览器切换账号和新浏览器恢复历史／聊天。

本阶段沿用现有 SQLite 和线程池。每用户额度、公平排队、持久化任务队列及数据库升级属于下一阶段。
