# BiliNote 管理员后台核心需求

- 版本：v0.2，精简评审稿
- 日期：2026-11-04
- 目标：让管理员知道系统是否正常、任务是否顺利完成，并能处理基本账号和任务问题。

## 1. 页面范围

在现有应用内提供管理员入口，保留三个页面：**系统总览、任务监控、用户管理**。基础资源信息放在总览中；模型、转写和下载配置继续使用现有页面。

## 2. 核心功能

### 2.1 系统总览

- 展示用户总数、视频任务总数、成功数、失败数、正在执行数和排队数。
- 展示当前问答执行数、排队数和最近失败的问答。
- 展示后端、任务调度器和推理服务的当前状态，异常时给出简要原因。
- 点击任务数量或失败记录，可进入对应的任务列表。

统计以当前未删除任务的最新状态为准；视频任务与问答分开统计。本版不统计历次重新生成的历史执行次数。

### 2.2 任务监控

- 分别查看全站视频笔记任务和 AI 问答任务。
- 列表展示任务编号、所属用户、视频标题或关联视频、当前状态、提交时间，以及可获得的处理耗时。
- 支持按用户、状态筛选，按任务编号搜索，列表分页展示。
- 视频任务详情展示当前处理阶段、使用的模型、失败原因；问答展示模型、状态及失败原因。
- 管理员可取消尚未执行的视频排队任务，并重试失败的视频任务。
- 重试保留原用户归属，遵守账号、模型及队列限制；重复点击不能产生重复执行。

任务状态应区分排队、处理、等待资源、等待重试、成功、失败和取消。问答按实际支持的状态展示。本版不提供运行中任务强制终止。

### 2.3 基础资源监控

直接放在系统总览中，显示：

- CPU 使用率。
- 内存使用量与总量。
- GPU 使用率、显存使用量与总量（设备支持时）。
- 数据所在磁盘的剩余空间与使用率。

只展示当前值和最近更新时间，每 10 秒自动刷新，并支持手动刷新。没有 GPU、采集失败或后端断连时显示实际状态；容器部署注明指标可见范围。

### 2.4 用户管理

复用现有用户管理，保留以下能力：

- 查看、搜索用户，展示账号状态、注册时间、最近登录和任务数。
- 创建普通用户。
- 启用、停用普通用户。
- 重置普通用户密码。
- 从用户记录跳转到该用户的任务列表。

停用或重置密码后撤销原登录会话。停用账号不删除其数据：已运行任务允许完成，尚未开始的任务停止领取。管理员账号继续通过现有服务器命令维护。

## 3. 基本要求

- 仅管理员可以访问后台；所有管理接口在后端校验权限。
- 任务监控展示运行信息和脱敏错误，沿用现有用户正文与文件隔离规则。
- 缺失的时间、耗时或指标显示“未知”或“未采集”，不能填入虚构数据。
- 列表使用服务端分页，页面刷新不加载全部笔记正文或转录。
- 显示加载、空数据和请求失败状态；管理操作返回明确结果。

## 4. 验收标准

1. 管理员能从总览发现异常，并进入对应任务查看阶段或失败原因。
2. 两个不同用户提交任务后，全站计数、任务归属和筛选结果正确。
3. 取消排队和失败重试有效，不重复执行，也不改变任务归属。
4. CPU、内存、磁盘及可用的 GPU 数据正常刷新，采集异常不会显示为正常。
5. 用户创建、启停和密码重置有效，普通用户无法调用管理接口。

本版交付以以上功能为准，暂不加入费用与配额、历史趋势、独立告警中心、日志检索、审计中心、备份清理和多节点管理。
